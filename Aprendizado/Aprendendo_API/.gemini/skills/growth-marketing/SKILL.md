# Growth Marketing

## Quando Usar

- Estruturar ou auditar a landing page de um produto
- Definir a hierarquia de informação para conversão
- Escrever headlines, CTAs, taglines ou copy de produto
- Mapear e otimizar o funil de aquisição/ativação
- Identificar por que usuários chegam mas não convertem
- Garantir que o app/site comunica valor antes de pedir ação

## Frameworks de Funil

### AIDA — Jornada de Persuasão

| Etapa | Objetivo | Elemento de design |
|-------|----------|--------------------|
| **Awareness** | Usuário reconhece o problema | Headline + hero visual |
| **Interest** | Usuário entende a solução | Benefícios + como funciona |
| **Desire** | Usuário quer a solução | Social proof + garantia |
| **Action** | Usuário converte | CTA claro e de baixo risco |

### AARRR — Métricas de Crescimento (Pirate Metrics)

| Etapa | Pergunta | Métrica-chave |
|-------|----------|---------------|
| **Acquisition** | Como os usuários chegam? | CAC, tráfego por canal |
| **Activation** | Tiveram a experiência "aha"? | Taxa de onboarding completo |
| **Retention** | Voltam? | DAU/MAU, churn |
| **Referral** | Indicam para outros? | NPS, taxa de convite |
| **Revenue** | Pagam? | MRR, LTV, conversão trial→pago |

> Otimize na ordem: Retention → Activation → Acquisition. Reter é mais barato que adquirir.

## Estrutura de Landing Page de Alta Conversão

```
┌─────────────────────────────────────────────┐
│  NAV — Logo + CTA secundário (login)         │
├─────────────────────────────────────────────┤
│  HERO (above the fold)                       │
│  Headline: [Benefício principal em 1 frase]  │
│  Subheadline: [Para quem + como]             │
│  CTA primário: [Verbo + benefício]           │
│  Hero visual: [produto em contexto de uso]  │
├─────────────────────────────────────────────┤
│  SOCIAL PROOF — Logos ou números de prova   │
├─────────────────────────────────────────────┤
│  3 BENEFÍCIOS-CHAVE                         │
│  [Ícone] Título — Uma frase de benefício    │
├─────────────────────────────────────────────┤
│  COMO FUNCIONA — 3 passos simples           │
├─────────────────────────────────────────────┤
│  DEPOIMENTO — Citação real com foto/nome    │
├─────────────────────────────────────────────┤
│  FAQ — Responde as 3 objeções principais    │
├─────────────────────────────────────────────┤
│  CTA FINAL — Repetição com garantia/risco   │
└─────────────────────────────────────────────┘
```

## Copywriting Framework

### Headline — Fórmulas Testadas

```
[Resultado desejado] sem [dor principal]
→ "Gerencie seus projetos sem planilha e sem reunião"

[Verbo de ação] + [resultado específico] + [tempo/contexto]
→ "Lance sua loja em 15 minutos, sem código"

Para [persona] que [situação]: [benefício]
→ "Para freelancers que odeiam cobrar: automatize sua fatura"
```

### CTA — Escrever pelo Resultado, Não pela Ação

| ❌ Genérico | ✅ Orientado a benefício |
|------------|------------------------|
| Enviar | Receber minha análise grátis |
| Cadastrar | Começar agora — é grátis |
| Comprar | Garantir minha vaga |
| Saiba mais | Ver como funciona em 2 min |

### Benefícios vs Features

Para cada feature, perguntar "e daí?" até chegar no benefício real:

```
Feature: "Sincronização em tempo real"
→ E daí? "Todos veem as mudanças instantaneamente"
→ E daí? "Sem conflito de versão de documento"
→ Benefício: "Toda a equipe sempre na mesma página — sem e-mail de 'versão final v3'"
```

### Tratamento de Objeções

Identificar as 3 objeções mais comuns e responder no copy:

| Objeção | Elemento de resposta |
|---------|---------------------|
| "É caro" | Comparação de custo, ROI calculado, trial gratuito |
| "É complicado" | "Como funciona em 3 passos", demo em vídeo |
| "Não confio" | Depoimentos reais, logos de clientes, garantia |
| "Não preciso agora" | Urgência real (vagas limitadas, prazo) ou custo da inação |

## CRO Checklist — Auditoria de Conversão

### Above the fold (sem scroll)
- [ ] A proposta de valor está clara em 5 segundos?
- [ ] O usuário-alvo consegue se identificar na headline?
- [ ] Há um CTA primário visível sem scroll?
- [ ] O visual ilustra o produto em uso real (não ícone genérico)?

### Hierarquia de informação
- [ ] Uma ação primária por página (não 3 CTAs disputando atenção)?
- [ ] O fluxo de leitura guia ao CTA (F-pattern ou Z-pattern)?
- [ ] Benefícios antes de features?
- [ ] Social proof antes do CTA principal?

### Fricção e confiança
- [ ] O CTA explica o que acontece depois ("sem cartão de crédito", "cancele quando quiser")?
- [ ] Há pelo menos um depoimento com nome real e contexto?
- [ ] As objeções principais são respondidas antes do CTA?
- [ ] Não há campos desnecessários em formulários de conversão?

### Mobile
- [ ] O CTA é visível e clicável em tela de 375px?
- [ ] O texto está legível sem zoom (mínimo 16px)?
- [ ] Não há pop-ups que bloqueiam o conteúdo no mobile?

## Passos

### 1. Discovery do produto e usuário

Antes de escrever uma palavra:
- Qual é a proposta de valor em uma frase? (Se não existir, definir antes de escrever a copy)
- Quem é o usuário principal? (Cargo, dor, contexto de descoberta do produto)
- Qual é a ação primária que o usuário deve tomar?
- Quais são as 3 maiores objeções de compra ou cadastro?

### 2. Auditar o funil atual

Mapear o estado atual com o framework AARRR:
- Onde os usuários chegam (canais) e qual é o volume
- Onde ocorre o maior abandono (Hotjar, Analytics, funil)
- Qual é a taxa de ativação atual (usuário fez a ação-chave)
- O que os usuários que ficam têm em comum

### 3. Priorizar por impacto

Usar o framework ICE para priorizar otimizações:
```
ICE Score = Impact × Confidence × Ease (1-10 cada)
```
Trabalhar primeiro nas mudanças de alto impacto + alta confiança.

### 4. Escrever e estruturar

Aplicar o `## Copywriting Framework` e a `## Estrutura de Landing Page`.
Escrever ao menos 3 variações de headline antes de escolher.
Revisar pela ótica do usuário cético — sem jargão, sem claim sem prova.

### 5. Revisar e entregar

Aplicar o `## CRO Checklist` antes de entregar ao time de implementação.
Definir a métrica de sucesso (ex: "taxa de cadastro na landing de X% para Y%").
Documentar o baseline antes de publicar.

## Checklist de Validação

- [ ] Proposta de valor definida em uma frase
- [ ] Persona e objeções principais documentadas
- [ ] Estrutura de landing page aplicada
- [ ] Headlines escritas com fórmulas testadas (ao menos 3 variações)
- [ ] CTAs orientados a benefício (não a ação genérica)
- [ ] Features traduzidas em benefícios reais
- [ ] Social proof incluído (número, depoimento ou logo)
- [ ] Objeções respondidas antes do CTA
- [ ] CRO Checklist aplicado
- [ ] Métrica de conversão definida antes do lançamento
- [ ] Copy revisado pelo olhar do usuário cético
